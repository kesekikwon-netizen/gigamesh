## 고치지 않아도 되는 제안

1. **3D 시점과 바닥판 겹침 단서가 어긋난다.** 기본 시점 `pitch_ = 14`(`View3D.h:33`)는 계산상 아래에서 올려다보는 각도다(`MeshRaster.cpp:27-28`: 낮은 z 가 카메라에 더 가까움 — verify.md 관찰과 같음). 바닥판은 명세대로 메시보다 먼저(뒤에) 그리므로(`View3D.cpp:97-116`), 아래에서 보면 판이 가려야 할 항아리 밑면이 판 앞에 그려진다. 바닥 단계의 핵심 피드백이 "바닥판에 닿았나"이므로, 확정 전에만 위에서 내려다보는 시점(예: pitch −20°)으로 열거나 판을 깊이 비교로 그리는 것을 권한다. 덧붙여 3D 머리 `위` 단추(`View3D.cpp:245`, pitch 89)도 같은 규약이라 실제로는 바로 아래에서 본다(이 JOB 이전부터 있던 동작).
2. R4: 3D 정보 줄 접지 문구를 `<span Malgun>` 로 통째 감싸지 말고 숫자는 모노, `mm` 는 `Faint`(`View3D.cpp:259`, `ArtifactDoc.cpp:460-461` 의 문구를 HTML 조각으로 쪼개거나 표시 쪽에서 감싸기). ctx 오른쪽도 `mm` 를 `Faint` 로.
3. R8: 상태줄 ④ 문구와 도판 자리 문구의 `(Enter)` 가 일반 글자다(`MainWindow.cpp:508`, `SheetView.cpp:84`). 기존 상태줄처럼 `<span style='font-family:Consolas'>Enter</span>` 정도로 키임을 드러내면 좋다. ctx 안내 끝의 `· Enter 확정` 과 바로 옆 kbd 배지 `Enter 확정` 이 겹친다(`:511`, `:255`) — 둘 중 하나로.
4. 수동 확정 뒤 배지가 `✓ 기준: 바닥판 기준 (사람 확정) · …` 로 "기준"이 두 번 나온다(`SheetView.cpp:253` + `ArtifactDoc.cpp:495`). 문구는 명세가 정한 값이라 후속에서 `바닥판 (사람 확정)` 등으로 다듬기.
5. 확정 전후로 3D 보조창 폭이 ≈453 px → ≈280 px 로 바뀐다(`shot_base` vs `shot_main`). 확정 뒤 폭은 JOB-002 와 같은 기존 동작(긴 배지·치수 띠 최소 폭)이지만, Enter 순간 화면이 출렁인다 — 레이아웃 폭 작업에서 배지 생략(elide)과 함께.
6. 확정 전에는 홈 페이지 `도면` 타일이 Action 색인데 누르면 막힌다. 화면당 하나 규칙은 지켜지지만, 확정 전엔 Idle 로 두면 "지금 누를 주 단추 = 이 자세로 확정" 이 앱 전체에서 하나가 된다.
7. 시작 화면·리본 `예제 유물` 은 지금처럼 확정 상태로 열린다(`MainWindow.cpp:61-62`, 명세 결정). 초보자가 ① 단계를 연습할 수 있게 후속에서 "바닥 정하기부터" 예제 진입점을 고려.
